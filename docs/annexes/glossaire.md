# Glossaire {#glossaire}

**Architecture** : la façon dont le code est organisé et découpé en morceaux. Comme le plan des pièces d'une maison. → [Chapitre 5](/guide/05-stack-et-architecture)

**Authentification** : la façon dont l'application vérifie qui est connecté (identifiant, mot de passe…).

**Autorisation** : ce qu'une personne connectée a le droit de voir ou de faire.

**Base de données** : l'endroit où l'application range ses informations (clients, factures…) de façon durable.

**Branche** : une copie de travail du projet dans Git, pour essayer des choses sans toucher à la version principale. → [Chapitre 3](/guide/03-git)

**Bug** : un comportement de l'application différent de celui attendu.

**Cahier des charges (spec)** : le document qui décrit en français ce que l'application doit faire. → [Chapitre 4](/guide/04-cahier-des-charges)

**CLAUDE.md** : le fichier de règles que Claude relit au début de chaque conversation. → [Chapitre 6](/guide/06-claude-md)

**Commit** : une « photo » du projet à un instant donné, enregistrée dans Git avec un message. → [Chapitre 3](/guide/03-git)

**Contexte** : tout ce que Claude a en tête pendant une conversation. Limité, et moins efficace quand il est plein. → [Chapitre 9](/guide/09-conversations)

**Déployer** : envoyer une nouvelle version de l'application sur le serveur en ligne. → [Chapitre 15](/guide/15-mise-en-ligne)

**Effort** : le niveau de réflexion de Claude avant d'agir (`low` à `max`). → [Chapitre 2](/guide/02-installer-et-regler)

**Environnement** : un exemplaire complet de l'application (développement, production…). → [Chapitre 15](/guide/15-mise-en-ligne)

**Git** : l'outil qui garde l'historique de toutes les versions du projet. → [Chapitre 3](/guide/03-git)

**GitHub** : un service en ligne qui héberge une copie des projets Git.

**Héberger** : faire tourner l'application sur un serveur accessible par Internet.

**Hook** : un automatisme qui se déclenche systématiquement à un moment précis du travail de Claude. → [Chapitre 14](/guide/14-skills-et-hooks)

**Mode plan** : mode dans lequel Claude réfléchit et propose un plan sans rien modifier. → [Chapitre 8](/guide/08-boucle-de-travail)

**Modèle** : la « version » de Claude utilisée (Opus, Sonnet, Haiku…). → [Chapitre 2](/guide/02-installer-et-regler)

**Production (prod)** : l'environnement réel, utilisé par les vrais utilisateurs avec les vraies données.

**Push** : envoyer ses commits sur GitHub.

**Régression** : quelque chose qui marchait et qui ne marche plus après une modification.

**Secret** : un mot de passe ou une clé d'accès. Jamais dans le code. → [Chapitre 13](/guide/13-securite)

**Skill** : une fiche méthode que Claude consulte quand c'est utile, ou que tu lances avec `/nom`. → [Chapitre 14](/guide/14-skills-et-hooks)

**Sous-agent** : un Claude auxiliaire, avec sa propre conversation, à qui le Claude principal confie une tâche (une relecture, par exemple). → [Chapitre 12](/guide/12-relecture)

**Stack** : l'ensemble des technologies utilisées par l'application. → [Chapitre 5](/guide/05-stack-et-architecture)

**Test** : une vérification automatique qui dit si une partie de l'application fonctionne comme prévu. → [Chapitre 11](/guide/11-tests)
